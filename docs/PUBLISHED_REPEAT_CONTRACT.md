# Публикация и повтор: единый контракт NEUROMIX

**Статус:** действующее продуктовое правило линии `tanyapi`. При конфликте со старыми заметками в `docs/agents/` приоритет имеют этот контракт, реализация и тесты. Выпуск подтверждается только после проверки production SHA.

## Главное правило

**Любая опубликованная готовая работа доступна для повтора**: исходная генерация, результат тренда, ремикс или повтор чужой работы. Происхождение (`source_feed_gen_id`, `action_type`) используется для истории и учёта, **но не запрещает повтор**.

Повторить означает воссоздать **выбранную публикацию** — с её собственными настройками, prompt/авторскими изменениями, моделью, сценарием и порядком слотов. **Нельзя** автоматически перенаправлять пользователя к первой работе или исходному тренду, у которого другой рецепт.

Единое правило относится к поддерживаемым фото- и видеомоделям (Wan, Seedance, Kling, Nano Banana и др.). Текущие capabilities модели и доступность provider проверяются в коде; ограничение модели объясняется отдельно, не как запрет автора.

## Повтор ≠ доступ к скрытым входным файлам

- `fixed` — автор разрешил повторно использовать конкретный сохранённый вход **на сервере**. Публичный DTO показывает только индекс, роль и binding; URL не раскрывается.
- `upload` — пользователь загружает **свой** файл на место закрытого. Это не запрет на повтор.
- `ImageN`/`VideoN`, роли и порядок сохраняются. Пустой обязательный слот требует загрузки; генерация не начинается «наугад».
- Публичное превью и разрешение на server-side use скрытого референса — разные настройки.
- Старые публикации без полного typed grant обрабатываются совместимыми путями; нельзя выдумывать право раскрыть закрытый файл.

Снятие публикации, потеря обязательного файла или отзыв явного `fixed` разрешения проверяются **до** provider submission/списания. Публикация в профиле (`is_profile_visible`) остаётся доступна в рамках отдельной проверяемой видимости после снятия из ленты; полное снятие прекращает публичный повтор.

## Реализация

| Поверхность | Файлы | Правило |
| --- | --- | --- |
| Фото/ремикс | `bot/miniapp.py`, `bot/handlers/generation.py` | Авторизация по **текущей** опубликованной работе; root ID — только история. `private_repeat_permission_source_id` сохраняет текущий источник для retries |
| Обычное видео / Seedance | `bot/handlers/miniapp_video_continuity_compat.py`, `bot/video_repeat_reference_contract.py` | Восстановить prompt и typed/legacy слоты выбранного видео, не отказывать только по ancestry |
| Wan 3 / Prime в ленте | `bot/services/wan3_prime_repeat.py`, `bot/wan3_prime_api.py` | Возвращать ID самой публикации и opaque hash, не исходный `trend_id` |
| Прямой кураторский тренд | `bot/services/wan3_prime_trends.py` | Отдельный путь повтора **самого тренда** |
| Telegram кнопки | `bot/handlers/miniapp_video_continuity_compat.py`, `bot/keyboards.py` | «Повторить» опубликованного результата ведёт к нему, не к предку |

Сервер обязательно проверяет initData/actor, текущий источник и разрешённые слоты, размеры/длительности media, quote/hash и idempotency. Отсутствующая публикация не должна открываться через unsafe fallback.

## Пользовательский сценарий

1. Открыть работу в ленте или публичном профиле и нажать «Повторить».
2. Форма восстанавливает **её** рецепт; скрытые URLs и приватные полные prompts остаются на сервере.
3. Пользователь меняет переменные, добавляет собственные фото/видео в `upload`-слоты.
4. Backend измеряет входящие видеосекунды, считает итоговую цену и требует подтверждения актуального quote. Присутствие видео **не** означает множитель ×2.
5. Сервер запускает задачу только один раз; terminal status обновляет Studio. Telegram доставка зависит от доступности личного чата.
6. Временный 5xx провайдера не должен оставлять permanent «автор запретил» и стирать заполненную форму.

`successful_runs_count` на плитках трендов считает только связанные завершённые задачи (`completed`), уникальные по task ID. `uses_count` включает принятые попытки и не заменяет успешные повторы.

## Ошибки и причины

| Сигнал | Корректная реакция |
| --- | --- |
| `repeat_permission_changed` | Server grant/recipe действительно изменён: открыть публикацию снова, не списывать |
| `404` / публикация снята | Отказ по текущему post, без обхода через предка |
| Не хватает media или `fixed` файл потерян | Попросить нужный `upload` файл / исправить загрузку до списания |
| Модель/режим недоступны | Показать ошибку модели, не «согласия автора» |
| Provider 5xx, сеть, stale quote | Сохранить черновик; корректно повторить или пересчитать цену |
