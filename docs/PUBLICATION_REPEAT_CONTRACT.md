# Повтор опубликованных генераций — единый продуктовый контракт

**Статус: действующее продуктовое правило; технические ограничения конкретных моделей перечислены ниже отдельно.** Источник правила — владелец продукта (подтверждение 2026-10-15). Реализация: PR [#320](https://github.com/Bambale0/banano_kling/pull/320), плюс последующие изменения, прошедшие отдельные релизные проверки.

## Главное правило

**Если завершённая работа опубликована в ленте или опубликованном доступном профиле, пользователь может повторить эту работу.** Правило одинаково для фото и видео: Wan, Seedance, Nano Banana, Kling, Grok, Genjutsu и других поддерживаемых моделей. Источник результата (`trend`, `remix`, `repeat`, обычная генерация), история его предков и `source_feed_gen_id` сами по себе не запрещают повтор.

Повтор открывает **именно ту публикацию, по которой нажали**, включая её собственные пользовательские изменения, модель/режим, продолжительность, формат и порядок пронумерованных референсов. Нельзя молча перейти к старому тренду-предку: результат может отличаться. Кнопки Telegram, Feed/Profile и ссылки Mini App должны вести к одному и тому же опубликованному источнику. Новые изменения пользователя применяются к сохранённому серверному рецепту, а не заменяют его одним числом или пустым промптом.

## Три независимых слоя, которые нельзя смешивать

1. **Право повторить публикацию:** работа завершена и прямо сейчас опубликована для этого зрителя. Привязка к чужому тренду или предыдущему повтору не создаёт запрета.
2. **Видимость / повторное использование конкретного референса:** его публичный preview и право закрепить исходный файл — разные настройки. Сервер использует скрытый URL лишь там, где сохранено разрешённое fixed-место. Остальные места пользователь заполняет своими файлами. Приватные URL и исходный скрытый промпт не выдаются в JSON/HTML/ошибках.
3. **Технические возможности выбранной модели:** нужный режим, тип файла, разрешение, длительность, качество, доступность media и provider API могут влиять на запуск. Не допускается приписывать техническую ошибку отзыву публикации.

Публикация не означает бесплатный запуск и не делает неподдерживаемый upstream режим поддерживаемым. Цена, право на входящие материалы, ownership медиа, quote/hash, дебит/refund, идемпотентность и provider payload проверяются перед списанием. Если модель или специализированный editor не поддерживает конкретный режим повтора, исправляется/добавляется его pipeline, а не вводится общий запрет «повтор нельзя».

## Точка истины и серверная проверка

- **Обычные фото:** `bot/miniapp.py` Feed remix / generate-image + `bot/handlers/generation.py`; проверка разрешения на закреплённые материалы берётся из **непосредственной опубликованной работы**, а `source_feed_gen_id` остаётся историей происхождения. Повторная автоматическая попытка использует сохранённый server-authorized `private_repeat_permission_source_id`, если он установлен.
- **Обычное видео, Seedance:** `bot/handlers/miniapp_video_continuity_compat.py` + `bot/video_repeat_reference_contract.py`. Client подаёт изменения; сервер восстанавливает приватный prompt и выбранные слоты и фиксирует действующий источник. Typed / legacy-публикации имеют разные контракты; отсутствие typed-дескриптора **не всегда** означает отсутствие legacy-пути.
- **Wan:** `bot/services/wan3_prime_repeat.py`, `bot/wan3_prime_api.py`, `frontend/miniapp-v0/components/forms/wan3-prime-form.tsx`. `source_feed_gen_id` в плане — ID **кликнутой** публикации; для curated trend есть отдельный `trend_id` путь. Нельзя подменять published-result повтором исходного trend. Server quote и transactional launch перепроверяют immutable plan/hash, входящие секунды видео и итоговую сумму.
- **Genjutsu и отдельные video editors:** отдельные `recipe`-маршруты (`docs/GENJUTSU_FEED.md`). Их режимы могут требовать иной формы. Публикация сама по себе не обходит ограничения провайдера.

## Пользовательский сценарий

`Лента/профиль → Открыть работу → Повторить → Редактор нужной модели → свои переменные и файлы → точная цена → подтверждение → задача → результат в Mini App и (при наличии чата) Telegram.`

Скрытость источника не должна мешать открытию формы. Неопубликованная/удалённая работа, потеря обязательного media, несуществующая модель или несовместимый режим должны показывать **различимые** ошибки. Ошибки сети/провайдера нельзя интерпретировать как отзыв согласия автора, черновик и референсы пользователя по возможности сохраняются.

## Приёмка каждой модели

Для каждого режима `original → publish → repeat → publish repeat → repeat again` с фото/видео и пользовательскими переменными проверить: ID выбранной работы, восстановленный серверный prompt, slots, замену input, фактический provider payload, итоговый quote, один дебит/refund, terminal статус, Mini App result/history и Telegram callback. Отдельно проверить снятие публикации, истечение media, приватность JSON и автоповтор failed task. Минимум один реальный пользовательский smoke до признания непроверенного режима полностью рабочим.

Продуктовый контракт не является свидетельством полного прохождения каждого сценария в production. Фактические результаты и открытые риски см. [POST_RELEASE_AUDIT_2026-10-16.md](POST_RELEASE_AUDIT_2026-10-16.md).
