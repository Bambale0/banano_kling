# Умные повторы с обязательными референсами

Умный повтор использует существующие обработчики генерации, тарифы и доставку.
Mini App получает подписанные поля, а исходный промпт, скрытые исходники и
provider mapping остаются на сервере. Telegram-кнопки опубликованных работ
переводят участников выпуска в ту же форму Mini App.

## Работа автора

В деталях собственной опубликованной завершённой работы доступен конструктор.
Автор задаёт подписи, подсказки, обязательность и ограничения MIME/размера,
длительности и сторон изображения. Каждый файл имеет отдельный стабильный
`slot_id`: поле допускает 0–1 или ровно 1 файл. Дополнительные файлы создаются
отдельными полями, чтобы переменная длина массива не сдвигала `@ImageN`.

Дополнительные поля разрешены только для поддерживаемых списков текущего
сценария. Возможности берутся из существующих model/upload adapters. Стартовый
кадр учитывается в общем image budget тех адаптеров, которые преобразуют его
в элемент списка. Смена порядка карточек не меняет provider index. Удаление
дополнительного поля не должно создавать пропуски или ломать prompt tags.

Сохранение создаёт новую версию. Открытый старый черновик требует обновления;
принятые задачи сохраняют прежний снимок. Закрепить исходник либо сделать поле
необязательным можно только при явном разрешении автора на использование
этого конкретного исходника в настройках публикации. Identity требует
собственных файлов пользователя.

Автор может создать именованные варианты замены. Пропущенное поле должно
иметь разрешённый оригинал. Переменные связаны с `{{name}}` исходного промпта;
пользователь видит только подпись переменной и вводит ограниченную строку.

## Запуск пользователя

Состояния файлов: EMPTY → UPLOADING → PROCESSING → READY либо FAILED.
READY устанавливает сервер после проверки владения, существования, структуры,
хеша и ограничений файла. Токен загрузки предотвращает позднюю привязку после
удаления или замены. Готовые файлы восстанавливаются из серверного черновика.

Повтор открывается в соответствующем экране фото/видео. Поле «Что изменить»
остаётся видимым: пожелания пользователя дополняют исходный промпт на сервере
через общий `compose_feed_remix_prompt`, не раскрывая и не заменяя его. Правки
сохраняются в черновике при расчёте и при выходе из повтора. Изменение текста
отменяет прежний расчёт. Закрытие возвращает к исходной публикации; повторное
открытие восстанавливает назначенные файлы и правки.

В форме явно указана модель исходной работы. Вместо общей области файлов
показаны только подписанные поля выбранного рецепта. Через «+» открываются
«Загрузить новый файл» и «Взять из сохранённых». Библиотека показывает превью
и имена; само её открытие не назначает файл обязательному полю. После проверки
поле показывает «Выбрано: имя файла», превью и обновлённый счётчик.
Сохранённый файл выбирается по `saved_reference_id`, а файл Wan — по
отдельному `wan3_media_id`: числовые ID этих хранилищ могут совпадать. Проверки владельца
и типа выполняются на сервере; URL и имя из клиента не определяют идентичность файла.
Черновик сохраняет ID медиа, имя, `asset_id` и стабильный `slot_id`, поэтому
одинаковые имена не смешивают файлы. Старые клиенты с URL проходят прежнюю
проверку владения и содержимого.

После заполнения полей пользователь отдельно рассчитывает стоимость и
подтверждает запуск. Изменение поля отменяет расчёт. Сервер повторно проверяет
актуальную публикацию, версию, файлы и цену, фиксирует снимок и допускает один
запуск операции. Все пользовательские и закреплённые входы имеют `asset_id`.

После потери ответа проверяется прежняя операция. Принятый запрос повторно
не отправляется провайдеру. При доказанном отказе без списания либо с полным
возвратом можно явно создать новый повтор. Неопределённый исход сохраняет
запрет повторной отправки. История Mini App доступна независимо от доставки
в Telegram. Wan сохраняет связь draft/intent/task в транзакции резервирования.

## Дополнительные фото в пользовательском повторе

Только в повторе **фото** есть отдельный необязательный блок
«Дополнительные референсы»: можно загрузить несколько изображений либо выбрать
свои сохранённые фото (например, маникюр, телефон, чехол). Назначение деталей
пользователь описывает в существующем поле «Что изменить». Дополнительные фото
не заполняют обязательные поля и не увеличивают их счётчик. У видео такого блока нет.

Общий бюджет берётся из действующих image/model adapters. Из него вычитаются
все исходные позиции, включая закреплённые/скрытые фото и добавленные автором
поля. Если свободного бюджета нет, форма объясняет ограничение; лишние файлы
не обрезаются молча. После уменьшения лимита ранее выбранные фото остаются
видимыми для удаления, а расчёт сверх лимита запрещён сервером.

API `open/update/quote` дополнительно возвращает `additional_image_limit` и
`additional_image_slots`; у видео это `0` и `[]`. Слоты `extra_image_N` существуют
только в пользовательском черновике и используют прежние операции
`begin/processing/ready/failed/remove`, проверку владельца и токены загрузки.
Шаблон автора и его версия не меняются. Пустые дополнительные слоты не нужны
для запуска; выбранный, но не проверенный/ошибочный файл необходимо дождаться
или удалить. Выбор и удаление отменяют прежний расчёт стоимости.

Компилятор добавляет выбранные дополнительные фото после всех исходных
позиций, включая закреплённые исходники. Пропуск после удаления уплотняется
только среди дополнительных фото: исходные `@ImageN` не смещаются. Дополнительные
слоты восстанавливаются при открытии и сохраняются при смене варианта замены.
Их ID/asset IDs входят в существующие snapshot, retention и структурированные
события. Фильтр чужих исходников допускает только принадлежащие пользователю
файлы из проверенного server-side capability текущего запроса, source и user;
клиентский JSON не разрешает повторное использование чужих скрытых фото.

Миграций схемы БД, новых тарифов и изменений video adapters нет. Старые клиенты
могут продолжать повтор без дополнительных фото. Выпуск использует прежнюю
настройку `smart_repeat_rollout`.

## Выпуск и совместимость

Настройка `smart_repeat_rollout` хранится в `bot_settings`:
`{"enabled": false, "telegram_ids": []}`. По умолчанию выпуск выключен.
Администратор может включить пилот по Telegram ID, включить всем или выключить
через конструктор. Сервер проверяет настройку; старые клиенты участников
выпуска получают `SMART_REPEAT_REQUIRED` вместо обхода формы. После отключения
принятые операции остаются доступны для восстановления и проверки.

Версии хранятся в `smart_repeat_templates`, черновики и снимки —
`smart_repeat_drafts`. Схема добавляется при старте SQLite/PostgreSQL;
`schema_postgres.sql` содержит тот же контракт для чистой установки. Черновики,
версии и снимки участвуют в графе сохранности медиа. Общая блокировка с Wan
retention закрывает гонку между удалением медиа и привязкой READY.

Однозначные публикации получают начальную схему при первом обращении.
Администратор может пакетно проверить старые публикации в диагностике;
неоднозначные возвращаются с `review_required`. Исходные медиа и связи не
удаляются. Автор исправляет разрешения/рецепт и сохраняет новую версию.

## API и диагностика

POST `/mini-app/api/repeat/{action}` использует существующую Telegram-аутентификацию.
Действия: `template`, `configure` (автор); `open`, `update`, `quote`, `launch`
(владелец черновика); `diagnostics` (владелец либо администратор);
`rollout`, `migration` (администратор). Клиент не передаёт hidden prompt,
provider payload, цену либо разрешение на чужие медиа.

Администратор открывает диагностику в деталях задачи, указывает task ID и
сравнивает ожидаемые поля с состоянием/asset ID снимка и суммами списания и
возврата. Диагностика не выдаёт URL приватных исходников.

Структурированные события `repeat_opened`, `slot_upload_started`, `slot_ready`,
`validation_failed`, `generation_requested`, `generation_created` содержат
user/source/draft/task/version/slot/asset IDs и модель там, где они известны.
Содержимое файлов, скрытые промпты и ключи доступа не записываются в события.

Для rollback достаточно выключить выпуск; версии, черновики и результаты
сохраняются. Обычный выпуск проходит PR → строгие CI gates → squash auto-merge
в `tanyapi` → production CI/autodeploy → проверка точного SHA и smoke.

## Переход из публикации и выбор сохранённого файла

При включённом выпуске кнопка повтора из ленты или профиля открывает единственный
форму по ID исходной публикации на соответствующем экране фото/видео. Обычный
генератор другой модели не открывается,
а устаревшие пресеты и запоздавшие ответы предыдущей ссылки не перехватывают
новый повтор. Закрытие формы возвращает к публикации в ленте или профиле автора.
Genjutsu сохраняет свой существующий специализированный переход.

Модель в форме берётся из серверного шаблона и подписана как модель исходной
работы. До загрузки шаблона заголовок не предполагает, что это видео или фото.
Для старого интерфейса отсутствие исходной модели в текущем каталоге означает
явную ошибку; замена первой доступной моделью не допускается.

Кнопка «Взять из сохранённых» открывает отдельную библиотеку с превью и именами;
её варианты не считаются уже заполненными полями. Файл попадает в счётчик обязательных
референсов только после выбора и серверной проверки READY. Наличие нескольких
файлов в библиотеке не заполняет поле автоматически и не разрешает запуск.
