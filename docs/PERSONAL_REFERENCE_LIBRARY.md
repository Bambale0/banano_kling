# Личные категории референсов

В своём профиле Mini App и в загрузчиках фото/видео/аудио есть кнопка **Мои референсы**.
Пользователь создаёт папки с собственными названиями, например «Одежда», сохраняет туда
несколько вариантов и выбирает их без повторной загрузки. Можно переименовать папку и
референс, убрать файл из папки, удалить папку или сохранить недавнюю загрузку в категорию.
Один референс может находиться в нескольких своих папках.

В персонализации повтора кнопка появляется рядом со «Своим вариантом», если автор
разрешил собственные изображения. Выбор из папки становится обычным личным референсом;
скрытый промпт и админский режим персонализации PR #387 не меняются.

Telegram-фото-пикер показывает категории и страницы файлов. Папки создаются и
редактируются в Mini App. Последние загрузки остаются доступны отдельным пунктом.
Переключение папок или удаление одного файла не сбрасывает остальные входы генерации.

## Хранение и приватность

Категории и членство находятся в `reference_categories` и `reference_category_items`.
Файлы остаются в существующем `static/uploads/refs/` и SavedReference. Добавление в
папку защищает запись от ротации последних загрузок и от очистки по возрасту. Загрузка
в папку сохраняет членство в той же транзакции, до pruning. Повторная загрузка тех же
байтов использует существующий SavedReference. Новые категории не создаются автоматически.

Имена папок не определяют провайдера, модель или роль входа. Это организация личных
файлов. Категории и ID референсов всегда проверяются по авторизованному владельцу;
caller-supplied `user_id`/`telegram_id` не используются как полномочия.

Удаление категории убирает её членства, сохраняя сами записи загрузок. Явное удаление
SavedReference из Telegram удаляет его членства через FK cascade. Физические файлы
освобождает существующая очистка осиротевших файлов с учётом владельцев/истории работ.
После снятия последнего членства к записи снова применяются обычные правила последних
загрузок. Сохранённые в папках записи не занимают их ограниченный список.

Пользователь не получает искусственную новую бизнес-квоту: сохраняются действующие
проверки размера/формата загрузки. Mini App и Telegram используют страницы, а не
обрезают библиотеку до первых 5/50/100 файлов.

## API и схема

Авторизованный POST `/mini-app/api/reference-library`:

- `categories` — свои папки и последние загрузки;
- `items` — содержимое своей папки, фильтр kind, offset, страница 40;
- `create_category`, `rename_category`, `delete_category`;
- `save_item`, `remove_item` — собственный reference_id и category_id.

В `/upload` JSON и multipart поддерживают необязательный `reference_category_id`.
Категория проверяется до записи байтов и повторно в транзакции сохранения. При удалении
категории во время загрузки запрос завершается ошибкой, без ложного успешного сохранения.

Схема additive; существующие референсы сохраняются. SQLite использует штатный init,
PostgreSQL — нативный bootstrap адаптера; общий DDL вынесен в `reference_library_schema.py`
и отражён в `schema_postgres.sql`. Категории пользователя и cleanup сериализуются одним
parent user lock в PostgreSQL; SQLite использует write transaction. Ночная очистка
блокирует владельцев saved refs в порядке ID до чтения кандидатов, включая полностью
категоризированные записи, чтобы remove/re-pin не потерял успешно сохранённое членство.

Откат к версии до этой функции требует сохранить защиту категорий в очистке: старые
pruner-ы не знают о закреплённых записях. Таблицы при откате не удалять.
