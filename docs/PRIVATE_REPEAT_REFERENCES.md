# Приватные референсы при повторе опубликованных фото и видео

**Действующий контракт:** [PUBLICATION_REPEAT_CONTRACT.md](PUBLICATION_REPEAT_CONTRACT.md). У опубликованной завершённой работы доступен повтор независимо от того, создана ли она из тренда, другого повтора или ремикса. Нельзя вводить запрет на основании `source_feed_gen_id` / `action_type`. Отдельно контролируется **использование конкретных скрытых файлов** и их доступность.

## Раздельные настройки

- **Публичная видимость ссылок/превью** (`feed_references_visible` и per-media selection) определяет, что можно показывать посетителю.
- **Серверный grant на закрепление оригинального media в повторе** (`feed_repeat_reference_selection`) определяет, что разрешено оставить fixed и передать провайдеру *без публикации URL*.
- **Заменяемый слот** (`upload`) требует пользовательского файла. Нельзя заменять скрытый файл открытой ссылкой, выдать его в API или угадывать недостающий input.

Для фото есть снимок выбранных оригинальных изображений в `generation_tasks.feed_repeat_reference_selection`; для typed-video используется versioned структура с `images` / `videos`, а для старого контента существует отдельный legacy-маршрут. Пустое разрешение на использование скрытого media **не отменяет саму возможность повторить публикацию**: сервер должен применить доступный сценарий с пользовательскими заменами, когда провайдерский pipeline это поддерживает.

## Источник и отзыв

При повторе опубликованного дочернего результата (`trend` / `repeat` / `remix`) источник — **эта** публикация: она хранит авторские изменения, настройки и собственную границу прав. Предок нужен для истории/атрибуции, но не для молчаливой замены рецепта или автоматического отказа.

Перед первым списанием и перед повторной отправкой провайдеру сервер проверяет актуальную публикацию, точное соответствие выбранных fixed URLs и существование разрешённых файлов. Для фото авторитетом является ID непосредственно выбранной работы; корневой `source_feed_gen_id` остаётся для accounting/lineage, `private_repeat_permission_source_id` — отдельный server-only ключ для проверок автоповтора.

Снятие публикации с публичных площадок либо отзыв соответствующего fixed grant запрещает дальнейшее использование **отозванного** media. Отсутствующий или неподдерживаемый input требует пользовательскую замену или отдельный совместимый pipeline. Уже отправленная провайдеру задача не может быть отменена задним числом изменением разрешений.

## Приватность и качество

- Сохранённые приватные URL и базовый скрытый промпт не возвращаются в DTO, recent history, публичных карточках, ошибках или клиентских логах.
- Файлы сохраняют позиции `ImageN`, `VideoN` и роли start/last-frame; удаление одного не сдвигает последующие слоты.
- Не смешивать авторские fixed-файлы с чужими пользовательскими upload вне server-owned контракта. Канонические и legacy aliases могут обозначать один файл; другой внешний URL не наследует разрешение.
- Не считать редактирование видео Seedance и смену персонажа обычным generic reference-mode без проверки специального editor.
- Незапрошенный повторный платеж/повторная отправка к провайдеру при неопределённом статусе недопустимы.

## Диагностика

`Повтор недоступен` не является достаточным объяснением. Проверять отдельно publication visibility, model capability, prompt availability, decoded grant and slot counts, media availability, quote/hash and user-specific auth. Для провайдерских 503, ошибок загрузки или сетевого timeout не переводить повтор в состояние «автор запретил». Использовать [troubleshooting.md](troubleshooting.md) и [POST_RELEASE_AUDIT_2026-10-16.md](POST_RELEASE_AUDIT_2026-10-16.md).
