# Robokassa — основной RUB checkout

В пользовательском UX Robokassa — первый и основной рублёвый способ оплаты. Пользователь видит её как «СБП / карта». Следом идёт KASSA как резервный способ, а Lava перенесена ниже в список дополнительных способов.

## Переменные окружения

```env
PAYMENT_PROVIDER=robokassa
ROBOKASSA_MERCHANT_LOGIN=<идентификатор магазина>
ROBOKASSA_PASSWORD1=<боевой пароль #1>
ROBOKASSA_PASSWORD2=<боевой пароль #2>
ROBOKASSA_HASH_ALGORITHM=md5
ROBOKASSA_TEST_MODE=false
ROBOKASSA_WEBHOOK_PATH=/robokassa/result
```

Для тестового режима дополнительно задаются отдельные `ROBOKASSA_TEST_PASSWORD1` и
`ROBOKASSA_TEST_PASSWORD2`, после чего `ROBOKASSA_TEST_MODE=true`. Боевые пароли не
используются как fallback для тестового режима.

Секреты хранятся только в runtime environment и не коммитятся.

## Настройки магазина Robokassa

- Result URL: `https://tanyapi.chillcreative.ru/robokassa/result`
- Result URL method: `POST`
- Success URL: `https://t.me/Neuromixx_bot`
- Success URL method: `GET`
- Fail URL: `https://t.me/Neuromixx_bot`
- Fail URL method: `GET`
- Hash algorithm: тот же, что в `ROBOKASSA_HASH_ALGORITHM` (сейчас `MD5`)

Result URL — единственный источник подтверждения оплаты для начисления бананов.
Success URL используется только как возврат пользователя после оплаты.

## Контракт

Checkout подписывается Password #1. Result URL проверяется Password #2. Перед
начислением дополнительно сверяются `InvId`, провайдер транзакции и `OutSum`.
Завершение платежа проходит через существующий атомарный payment completion flow,
поэтому повторная доставка callback возвращает `OK{InvId}` без повторного начисления.

FreeKassa / KASSA остаётся резервным рублёвым способом. Lava остаётся доступна как дополнительный способ ниже основного и резервного RUB checkout.


## Номенклатура новых оплат

Обе поверхности (Telegram и Mini App) передают подписанный `Receipt` с одной
позицией: «Пополнение баланса NEUROMIX для генерации изображений и видео,
{total_credits} кредитов». Количество — 1 пакет; сумма — фактически оплачиваемая
цена пакета в рублях, ровно `OutSum`. Бонусные кредиты включены в количество
кредитов в названии, но не увеличивают денежную сумму.

Обязательная конфигурация перед выпуском:

```env
ROBOKASSA_RECEIPT_TAX=none
```

`none` означает «без НДС», а не ставку налога НПД 4%/6%. Для магазина Тани
статус самозанятой подтверждён владельцем 2026-10-06. Для другого продавца ставку
нужно подтвердить отдельно. Без явной допустимой ставки новые checkout блокируются
до создания транзакции; ранее созданные платежи и ResultURL продолжают работать.

`sno` не передаётся: `npd` не является значением перечисления СНО Robokassa.
`payment_method` и `payment_object` по умолчанию отсутствуют (используются настройки
кабинета). Не назначаем `full_payment` автоматически при пополнении будущего баланса.
При подтверждённой кассовой классификации можно явно задать
`ROBOKASSA_RECEIPT_PAYMENT_METHOD` и `ROBOKASSA_RECEIPT_PAYMENT_OBJECT`; поддерживаемые
предметы для этого сервиса: `service`, `payment`, `intellectual_activity`,
`property_right`. Кассовый режим и НПД нельзя смешивать.

Для автоматического чека НПД недостаточно изменения сайта: в кабинете должны быть
активны «Робочеки СМЗ» и разрешение интеграции с «Моим налогом». Эти настройки данным
изменением не проверяются и не меняются. Платёжная квитанция не заменяет чек НПД.
Email, если передан вызывающим кодом, сохраняется; выдуманных контактов нет,
контакт покупателя собирает платёжная форма.

Технический контракт: компактный JSON UTF-8 → URL encoding → включение ровно этого
значения перед Password #1 в подпись → обычный urlencode внешнего query. Поэтому
`Receipt=%257B...` в готовом URL ожидаем: разбор query оставляет `%7B...`.
Текущий короткий GET checkout с одной позицией сохранён; при расширении корзины
нужно перейти на рекомендуемый документацией POST. ResultURL-подпись не меняется.

Изменение касается только вновь созданных ссылок. Старые ссылки и пропущенные
чеки автоматически не исправляются. Отдельную сверку исторических оплат и
регистрацию пропущенных чеков следует согласовать с Robokassa/бухгалтером, исключив
дубли. Не создавать коррекции или возвраты автоматически.
