# Seedance 2.0 / 2.5: резервный Нейроныч

Основной провайдер остаётся KIE. Обе пользовательские поверхности используют общий сервис.

## Переключение

- После явного отказа createTask с разрешённым кодом возвращается постоянный ID резервного маршрута.
- Платный резерв запускается первым опросом только после сохранения активной пользовательской generation_tasks. Потерянный до привязки receipt не запускает платную работу.
- После подтверждённого терминального отказа принятой KIE-задачи её сохранённый payload используется для одной резервной попытки той же модели.
- Таймаут, некорректный JSON, отсутствие taskId в ответе с неизвестным приёмом и 422 не переключают провайдера.
- Неизвестный приём Нейронычем повторяется с тем же Idempotency-Key и тем же сохранённым wire payload после истечения lease. Параллельные проверки защищены транзакционным claim.
- Уже возвращённая, завершённая или заменённая задача не запускает резерв.

## Контракт и ограничения

Используются POST /v1/videos/generations, GET /v1/videos/{request_id} и авторизованная загрузка /content. Модели: seedance-2.0 и seedance-2.5.

Текст, изображения, видео, аудиореференсы, кадры и 2.5 edit сохраняются при совместимости с контрактом. В частности, 2.5 edit получает duration=-1 и aspect_ratio=adaptive. При несовместимых параметрах остаётся исходная ошибка; параметры не подменяются.

Нейроныч не поддерживает выключенный звук. Возврат последнего кадра, MOV, web_search=true и nsfw_checker=true также не включены в подтверждённый резервный контракт. Эти запросы не переключаются. KIE-only поля даже с обычными значениями не передаются: живой смок выявил downstream invalid_request при таком payload. Обычный резерв использует стандартный звук и MP4.

Адаптер сохраняет готовое видео в static/uploads/seedance_fallback (каталог исключён из суточной очистки) и отдаёт общий KIE-shaped статус с исходным локальным task_id. Секретный /content URL не передаётся клиенту. Подписанные ссылки провайдера не используются как постоянное хранилище.

## Конфигурация

| Переменная | Значение по умолчанию | Назначение |
| --- | --- | --- |
| SEEDANCE_FALLBACK_PROVIDER | neironych | off отключает новые переключения; принятые резервные задачи продолжают опрашиваться |
| SEEDANCE_FALLBACK_CREATE_CODES | 402,429,455,500,501,503,505 | Только явные KIE application-level createTask отказы без ID принятой задачи |
| NEIRONYCH_API_KEY | существующий секрет | Обязателен для новых резервных запросов |
| NEIRONYCH_API_BASE_URL | существующий адрес сервиса | Общий с админской лабораторией |
| NEIRONYCH_HTTP_TIMEOUT_SECONDS | существующий таймаут | HTTP и длительность защитного lease |

Новая таблица seedance_provider_routes добавляется идемпотентно. Для PostgreSQL используется execute_native_ddl и advisory lock, потому что legacy SQL-адаптер пропускает обычный CREATE TABLE. Таблица также включена в schema_postgres.sql.

## Восстановление и деньги

2.5 использует текущий reconciler, 2.0 — текущий watchdog (проверка задач старше двух минут, цикл раз в минуту). Канонические callbacks и recovery используют общий Market status seam. Резерв не вызывает повторного списания или создания нового платёжного события.

Watchdog не возвращает деньги по возрасту при ready/submitting/submitted резерве без готового результата. Подтверждённый fail распознаётся немедленно на следующем цикле и передаётся существующему атомарному механизму ошибки/возврата.

При неизвестном приёме длительный отказ API может оставить задачу ожидающей: нужно продолжать reconciliation по сохранённому ключу, а не создавать новый запрос или возвращать деньги без проверки.

## Проверки

Офлайн: tests/test_seedance_provider_fallback.py; для настоящего PostgreSQL задайте TEST_SEEDANCE_POSTGRES_URL на отдельную тестовую БД. Каждый тест создаёт и удаляет только собственную случайную схему.

Платный smoke, только с явным разрешением владельца:

```bash
python -m scripts.smoke_seedance_neironych_fallback --confirm-live \
  --database-path /tmp/seedance-fallback-smoke.db \
  --evidence-path /tmp/seedance-fallback-evidence.json
```

Смок подменяет отказ KIE кодом 402, но отправляет два настоящих запроса Нейронычу, опрашивает их и сохраняет/проверяет полученные файлы. Пользовательская БД не используется. Для продолжения после перезапуска передайте те же пути.

Завершённые основные KIE-маршруты удаляются после подтверждения терминального статуса. У завершённого резерва остаются только ID/URL результата и модель; приватный prompt/media payload очищается. Ошибки статуса/скачивания Нейроныча оставляют текущую задачу ожидающей и не прерывают reconciliation следующих строк. Один вызов polling делает не более одного основного HTTP GET.
