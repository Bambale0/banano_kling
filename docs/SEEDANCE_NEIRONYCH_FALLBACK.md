# Seedance 2.0 / 2.5: выбор primary и fallback

Telegram и Mini App используют общий маршрутизатор. Для нового production-маршрута задаются `SEEDANCE_PRIMARY_PROVIDER=neironych` и `SEEDANCE_FALLBACK_PROVIDER=kie`. Отсутствующая настройка primary сохраняет историческое поведение KIE → Нейроныч. Выбор провайдера не меняет цены и пользовательские формы.

## Нейроныч → KIE

- Новый локальный receipt сохраняется до платного запроса. Нейроныч запускается только после привязки активной `generation_tasks`.
- Сохраняются точный промпт, порядок image/video/audio, формат, разрешение и длительность. Режим edit передаётся отдельной внутренней метаинформацией.
- Подтверждённые create-отказы HTTP 400/401/402/403/404/422/429 и терминальные `failed`/`expired` запускают KIE, если он выбран резервом.
- HTTP 409/5xx, timeout и сетевые ошибки Нейроныча считаются неопределённым приёмом: повторяется тот же payload с тем же ключом идемпотентности. KIE в этом случае не запускается.
- Параллельные pollers и возвраты сериализуются через активную generation и атомарный claim. KIE создаётся только один раз; внутренний task ID не меняется. Внешний KIE ID хранится в маршруте и используется только для polling. KIE callback исключён из этой резервной отправки, чтобы внешний ID не обошёл локальный receipt.
- Если параметры не поддерживаются Нейронычем (например, отключённый звук), до первого платного запроса выбирается KIE и исходные параметры сохраняются. При выключенном fallback возвращается ошибка совместимости.
- Маршрут уже принятой задачи зафиксирован: последующее изменение конфигурации не отменяет её обработку. Для Seedance 2.5 primary больше не требует KIE-ключ для самого запуска через Нейроныча; ключ нужен при фактическом использовании KIE.

KIE не имеет подтверждённого идемпотентного create-контракта. Неопределённый приём его резервной отправки получает `kie_uncertain` (или остаётся `kie_submitting` при аварийном завершении процесса) и блокирует автоматический повтор/возврат. Лог `Seedance KIE fallback needs reconciliation` содержит локальный task ID. Оператор должен сверить принятие у KIE и восстановить внешний ID в существующем маршруте; создавать новую задачу или возвращать средства вслепую нельзя. Если ID присутствует в ответе даже вместе с ошибкой, он сохраняется и задача опрашивается.

Фазы `kie_ready`, `kie_submitting`, `kie_uncertain`, `kie_submitted` включены в защиту watchdog от преждевременного возврата. Терминальная ошибка второго провайдера передаётся штатному механизму возврата без нового списания и без цикла между провайдерами. Готовый результат KIE проходит существующую продуктовую доставку/хранение; готовое видео Нейроныча предварительно сохраняется локально.

## Исторический маршрут KIE → Нейроныч

- После явного отказа createTask с разрешённым кодом возвращается постоянный ID резервного маршрута.
- Платный резерв запускается первым опросом только после сохранения активной пользовательской generation_tasks. Потерянный до привязки receipt не запускает платную работу.
- После подтверждённого терминального отказа принятой KIE-задачи её сохранённый payload используется для одной резервной попытки той же модели.
- Таймаут, некорректный JSON, отсутствие taskId в ответе с неизвестным приёмом и 422 не переключают провайдера.
- Неизвестный приём Нейронычем повторяется с тем же Idempotency-Key и тем же сохранённым wire payload после истечения lease. Параллельные проверки защищены транзакционным claim.
- Уже возвращённая, завершённая или заменённая задача не запускает резерв.

## Контракт и ограничения

Используются POST /v1/videos/generations, GET /v1/videos/{request_id} и авторизованная загрузка /content. Модели: seedance-2.0 и seedance-2.5.

Текст, изображения, видео, аудиореференсы, кадры и 2.5 edit сохраняются при совместимости с контрактом. В частности, 2.5 edit получает duration=-1 и aspect_ratio=adaptive. В историческом KIE-first маршруте при несовместимых параметрах остаётся исходная ошибка. В Neironych-first маршруте совместимый резерв KIE выбирается до первой платной отправки. Параметры не подменяются.

Нейроныч не поддерживает выключенный звук. Возврат последнего кадра, MOV, web_search=true и nsfw_checker=true также не включены в подтверждённый резервный контракт. В KIE-first маршруте эти запросы не переключаются на Нейроныча; при Neironych-first они отправляются KIE без изменения настроек, если резерв включён. KIE-only поля даже с обычными значениями не передаются: живой смок выявил downstream invalid_request при таком payload. Обычный резерв использует стандартный звук и MP4.

Адаптер сохраняет готовое видео в static/uploads/seedance_fallback (каталог исключён из суточной очистки) и отдаёт общий KIE-shaped статус с исходным локальным task_id. Секретный /content URL не передаётся клиенту. Подписанные ссылки провайдера не используются как постоянное хранилище.

## Конфигурация

| Переменная | Значение по умолчанию | Назначение |
| --- | --- | --- |
| SEEDANCE_PRIMARY_PROVIDER | kie | neironych включает новый primary для обеих Seedance; kie сохраняет прежний порядок |
| SEEDANCE_FALLBACK_PROVIDER | противоположный primary | kie / neironych / off; в production задавать явно, чтобы прежняя env-настройка не отключила новый резерв |
| SEEDANCE_FALLBACK_CREATE_CODES | 402,429,455,500,501,503,505 | Только явные KIE application-level createTask отказы без ID принятой задачи |
| NEIRONYCH_API_KEY | существующий секрет | Обязателен для новых резервных запросов |
| NEIRONYCH_API_BASE_URL | существующий адрес сервиса | Общий с админской лабораторией |
| NEIRONYCH_HTTP_TIMEOUT_SECONDS | существующий таймаут | HTTP и длительность защитного lease |

Новая таблица seedance_provider_routes добавляется идемпотентно. Для PostgreSQL используется execute_native_ddl и advisory lock, потому что legacy SQL-адаптер пропускает обычный CREATE TABLE. Таблица также включена в schema_postgres.sql.

## Восстановление и деньги

2.5 использует текущий reconciler, 2.0 — текущий watchdog (проверка задач старше двух минут, цикл раз в минуту). Канонические callbacks и recovery используют общий Market status seam. Резерв не вызывает повторного списания или создания нового платёжного события.

Watchdog не возвращает деньги по возрасту при ready/submitting/submitted резерве без готового результата. Подтверждённый fail распознаётся немедленно на следующем цикле и передаётся существующему атомарному механизму ошибки/возврата.

При неизвестном приёме длительный отказ API может оставить задачу ожидающей: нужно продолжать reconciliation по сохранённому ключу, а не создавать новый запрос или возвращать деньги без проверки.

## Проверки

Офлайн: tests/test_seedance_provider_fallback.py; для настоящего PostgreSQL задайте TEST_SEEDANCE_POSTGRES_URL на отдельную тестовую БД. Каждый тест создаёт и удаляет только собственную случайную схему.

Платный smoke, только с явным разрешением владельца:

```bash
python -m scripts.smoke_seedance_neironych_fallback --confirm-live \
  --database-path /tmp/seedance-fallback-smoke.db \
  --evidence-path /tmp/seedance-fallback-evidence.json
```

Смок подменяет отказ KIE кодом 402, но отправляет два настоящих запроса Нейронычу, опрашивает их и сохраняет/проверяет полученные файлы. Пользовательская БД не используется. Для продолжения после перезапуска передайте те же пути.

Завершённые основные KIE-маршруты удаляются после подтверждения терминального статуса. У завершённого резерва остаются только ID/URL результата и модель; приватный prompt/media payload очищается. Ошибки статуса/скачивания Нейроныча оставляют текущую задачу ожидающей и не прерывают reconciliation следующих строк. Один вызов polling делает не более одного основного HTTP GET.

## Дополнительные гарантии

Обычные новые 2.5 text/reference запросы используют первый фиксированный формат (по умолчанию 16:9), одинаковый на backend и в публичной форме. Явный выбор Авто и старые сохранённые рецепты не подменяются; frames/edit сохраняют adaptive.

SEEDANCE_FALLBACK_CONTENT_ATTEMPTS (по умолчанию 3) ограничивает число reconciliation-попыток скачивания готового видео. Перед скачиванием берётся lease; после исчерпания бюджета задача получает терминальную ошибку content_unavailable и существующий механизм возврата. Внутренние HTTP-retries клиента остаются ограниченными отдельно. Ошибка статуса или отсутствующий API-ключ сохраняет неизвестный исход ожидающим и не останавливает другие строки.

SEEDANCE_FALLBACK_ORPHAN_TTL_SECONDS (по умолчанию 86400) задаёт срок жизни непривязанных ready/primary записей без request_id. Очистка выполняется при новых регистрациях и в штатном цикле housekeeping; активные связанные и неизвестные принятые запросы не удаляются. Все терминальные резервные ошибки очищают private payload; успешные основные маршруты удаляются.

Auto-длительность сама по себе не означает edit. Явный video_editing/identity_transfer передаётся в резерв отдельной внутренней метаинформацией и не добавляется в KIE wire body. Обычный Auto reference, включая административные и доверенные тренды, не преобразуется в edit: при несовместимости остаётся KIE-ошибка без повторной отправки другому провайдеру.


Для нового порядка провайдеров используйте изолированный платный smoke:

    python -m scripts.smoke_seedance_primary_routing --confirm-live --model seedance-2.5 --database-path /tmp/seedance-primary-smoke.db --evidence-path /tmp/seedance-primary-smoke.json

Параметр --force-primary-rejection имитирует только отказ Нейроныча и запускает реальную генерацию KIE. Для отдельного сценария используйте другую пару путей БД/evidence; для продолжения незавершённого сценария — те же пути. Повторите отдельно для seedance-2.0. Секреты берутся из существующего окружения; production DB не используется.
