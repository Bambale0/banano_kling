# Домен приложения ВКонтакте

Канонический адрес: **https://vk.neuromixbot.com/**, приложение должно открываться в корне `/`.
Telegram продолжает использовать свой существующий адрес и путь.

## Текущее состояние и выпуск VK-only — 09.11.2026

- Корень домена обслуживает отдельный статический VK-export; активная ревизия
  записывается в `/revision.txt`, а публикация выполняется атомарной заменой
  симлинка `/var/www/vk.neuromixbot.com/current`.
- `/mini-app/api/*` проксируется в тот же backend, что и Telegram Mini App.
- Публичный вход разрешён любому пользователю только по свежей подписанной
  строке запуска VK. Связанный пользователь открывает общую студию; несвязанный
  видит самостоятельный VK-вход с переходом в действующий нативный VK-бот,
  а двухстороннее связывание Telegram доступно по желанию.
- Настройки, sandbox wallet и коммерческие редакторы остаются закрытыми
  администраторскими поверхностями. Общий баланс и задачи принадлежат связанному
  legacy-пользователю Telegram; отдельный VK-баланс не создаётся.
- Это не перенос накопленного users.balance из независимого текстового VK-бота.
  До отдельной финансовой миграции такой остаток сохраняется в старой VK-базе
  и не суммируется с Telegram credits; преждевременное объединение может
  привести к повторным начислениям при позднем платеже или возврате.

## VK-only fallback до финансовой миграции

После проверенного signed-launch VK-only пользователь не должен создавать
Telegram-аккаунт ради доступа к уже работающим генерациям в нативном VK-боте.
Профиль account-preview/me возвращает vk_community_id из серверной настройки
VK-доставки только для VK identity; клиент не получает его из неподписанного
URL и не подставляет фиксированный ID сообщества. При наличии настроенного
положительного ID ссылка ведёт в диалог сообщества https://vk.com/im?sel=-ID.
Если ID отсутствует, никакой случайный чат не открывается и показывается
понятное сообщение. Подписанный пользователь может отдельно и добровольно
подтвердить привязку Telegram; неподписанный не видит ни чат-ссылки, ни
контента. Отсутствие Telegram по-прежнему не даёт доступа к защищённым
legacy-TG API генерации, к чужим данным, live-кошельку или платежам.

Это доступный релизный маршрут для VK-only через существующий текстовый VK-бот,
не утверждение полной VK-only функциональности внутри общей Mini App. Полная
VK-only студия и финансовое объединение требуют отдельного cutover,
проверенных legacy writers и согласования pending платежей по #408/#414.
При rollout проверить, что ID сообщества совпадает с работающим VK-ботом
(в проверенном production на момент реализации — совпадал). Изменение секрета
Mini App и полноценная приёмка мобильного клиента VK остаются отдельными
операционными gates, а не доказанными этой UI-доработкой.

## Исторический этап до первого admin-preview релиза

Изначально домен был опубликован только с maintenance-vhost и без приложения.

Реализована отдельная сборка `npm run build:vk`: NEXT_PUBLIC_MINIAPP_BASE_PATH=/, NEXT_PUBLIC_MINIAPP_PLATFORM=vk, NEXT_PUBLIC_MINIAPP_API_BASE=/mini-app/api. Неопределённый base path сохраняет /mini-app для Telegram. VK-экспорт использует ресурсы /_next в корне; post-export patch учитывает выбранный префикс, inline CSS и версии ресурсов. Telegram SDK и ready/expand bootstrap в VK-сборке не запускаются. Прямой вход без VK launch показывает предложение открыть приложение из ВКонтакте; сохранённый Telegram initData не используется. Это выбор поверхности, не авторизация: сервер по-прежнему проверяет подпись, срок и allowlist администратора.

На этапе подготовки проверены обе статические сборки и TypeScript; 3 проверки export-конфига/постобработки; 89 Jest suites / 676 tests; браузерные сценарии прямого входа, отказа обычному пользователю и интерфейса администратора на 430px и 1280px. Browser API был замокан: реальная VK-подпись и доступ из кабинета этим не подтверждались.

При первом admin-preview релизе проверенная сборка и API были привязаны к отдельному vhost. Публичное открытие остаётся отдельным этапом после полной приёмки. Наличие VK-параметров в URL само по себе не предоставляет доступ.

В кабинете VK требуется указать https://vk.neuromixbot.com/ как URL приложения; кабинет на этом этапе не менялся. Публичная оферта не менялась.

## Оставшиеся условия публичного запуска

Код и политика публичного входа подготовлены. До фактического открытия необходимо
выпустить новый защищённый ключ Mini App вместо опубликованного в чате, безопасно
обновить `VK_MINI_APP_SECRET`, увеличить revision политики для инвалидации старых
сессий и повторить реальную мобильную приёмку. Секреты не хранятся в Git,
документации или frontend-сборке.


## Уточнение пользовательского сценария — 06.11.2026

В текстовом ВК-боте требуется только нативная кнопка «Открыть приложение» (`open_app`) из companion PR tanyavk#65. Сценарии текстового бота не переносятся и не перерабатываются. Общая апка использует согласованные аккаунты и серверные данные, а не отдельную копию Telegram UI и данных для ВК. Это уточнение не отменяет требования безопасной общей финансовой системы.

Апка должна открываться сразу на весь доступный экран клиента ВК. VK entry теперь занимает как минимум 100dvh и всю доступную ширину (контент ограничен по ширине для читаемости). Нативный запуск использует app_id; обычная URL-кнопка на домен не заменяет native Mini App launch и подписанные параметры.

Важно для приёмки: CSS 100dvh заполняет viewport приложения, но не является доказательством системного fullscreen или скрытия оболочки ВК. В официальных типах VK Bridge проверены VKWebAppResizeWindow (размер iframe) и VKWebAppSetViewSettings (цвета/status-bar style); отдельного fullscreen-метода в проверенном контракте нет. Не добавлять выдуманные VKWebAppExpand/VKWebAppRequestFullscreen и не считать resizeWindow системным fullscreen. Реальное поведение запуска необходимо проверить в мобильном клиенте с настоящим app_id.

Источник контракта: https://github.com/VKCOM/vk-bridge/blob/master/packages/core/src/types/data.ts .

## Общая Mini App для ТГ и ВК — 06.11.2026

Текущая реализация не копирует Telegram Mini App и не создаёт отдельный
баланс для ВК. После подписанного входа ВК выдаётся короткоживущая непрозрачная
сессия. Она хранится только в памяти страницы и на каждом API-запросе
преобразуется сервером в уже связанного legacy-пользователя Telegram.

Обязательные свойства:

- связь ТГ↔ВК подтверждается обеими сторонами; несвязанный VK-аккаунт видит
  только экран связывания;
- отдельный пользователь и отдельный баланс для ВК не создаются;
- bootstrap, студия, фото, видео, Motion, тренды, лента, сервисы, профиль,
  история, задачи, референсы, повторы, партнёрский раздел, WAN, Genjutsu и
  Kling 4 используют существующие API и владельца данных;
- тариф и creator-условия берутся из существующего профиля связанного
  пользователя, поэтому ТГ и ВК видят одинаковую стоимость и общий баланс;
- в VK доступны только платёжные маршруты Lava; остальные провайдеры скрыты
  в интерфейсе и дополнительно отклоняются сервером с 403;
- предложение разрешить Telegram-боту писать не блокирует VK Mini App;
  текстовый VK-бот не изменяется, кроме уже выпущенной нативной кнопки;
- публичная сессия требует проверенной подписи, app ID, свежего timestamp,
  активного аккаунта и текущей revision политики; VK admin allowlist проверяется
  дополнительно только для административных инструментов. Изменение политики
  инвалидирует старые сессии.

Решение о публичном открытии принято 08.11.2026. Обычный подписанный пользователь
получает только собственную сессию; без подтверждённой связи с Telegram студия
не монтируется. Клиентские admin-флаги не дают полномочий. Публичная оферта не
менялась.

Проверки релизного контура: backend-контракты общей идентичности, платежей,
банов и специальных видеомаршрутов; полный Jest; ESLint; обе Next.js-сборки;
Chromium smoke на 430px и 1280px с проверкой общего интерфейса и отсутствия
Telegram SDK в VK-сборке.

## Платформенные ссылки — 07.11.2026

Публичные ссылки общей Mini App формируются по аутентифицированной поверхности, а не по Telegram-боту по умолчанию:

- из Telegram: `https://t.me/<bot>?startapp=<route>`;
- из VK: `https://vk.com/app<vk_app_id>#<route>`.

Правило применяется к трендам, публикациям и повторам ленты, профилю, партнёрской ссылке и ссылке опубликованной генерации. В VK поля совместимости `bot_link`/`referral_bot_link` также возвращают VK Mini App URL, чтобы старый UI не мог вывести пользователя в Telegram. Кнопка пересылки использует VK Share, а raw hash (`#prompt_…`, `#feed_…`, `#remix_…`, `#profile_…`, `#ref_…`) разбирается как входной маршрут. App ID берётся из серверной политики платформы и передаётся только через аутентифицированный VK-контекст; в бизнес-логике он не захардкожен.

Ссылки, которые по назначению ведут в Telegram для подтверждения связывания аккаунтов или разрешения Telegram-боту писать, остаются Telegram-ссылками. Это не навигация внутри VK Mini App.
