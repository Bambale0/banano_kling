# NEUROMIX: осторожная очистка диска 20.10.2026

Игорь разрешил очистить диск с сохранением референсов пользователей, трендов
и повторов. Удалялись только восстанавливаемые кэши и проверенные старые
установки VS Code Server. Пользовательские медиа, базы, volumes, контейнеры,
исходники, рабочие копии, логи и резервные копии не удалялись.

Прирост доступного места: **28 393 742 336 байт = 26,44 GiB**. Округлённый
вывод `df -h` после очистки: **110G свободно** из 871G.

Это дополнительный результат именно этой операции. До её первого удаления
на хосте уже осталось 25 Docker-образов вместо 100 из предыдущего аудита,
а свободное место выросло до 83 GiB. Предлагавшиеся три старых образа уже
отсутствовали. Эта предыдущая очистка не приписывается действиям ниже.

## Выполненные удаления

| Объект | Действие | Подтверждение |
| --- | --- | --- |
| Старый BuildKit cache | `docker builder prune --force --filter until=24h --reserved-space 10GB` | Docker сообщил `Total: 11.29GB`; cache уменьшился с 29,93 до 18,64 GB. Образы, контейнеры и volumes не являются целью этой команды. |
| npm download cache | `npm cache clean --force` | До очистки `_cacache` занимал около 7,6 GiB. По локальному исходнику npm 10.9.8 проверено: команда удаляет только `/root/.npm/_cacache`; `_npx`, установленные `node_modules` и настройки сохранены. |
| pip-tools HTTP cache | `python -m pip --cache-dir /root/.cache/pip-tools cache purge` | Удалено 2 910 cache-файлов; осталось около 18 MiB вместо 2,4 GiB. |
| pip download cache | `python -m pip cache purge` | Удалено 14 cache-файлов. Установленные Python-пакеты и virtualenv не удалялись. |
| Неиспользуемые VS Code Server | Удалено 10 каталогов `Stable-<commit>` старше 60 дней под `/root/.vscode-server/cli/servers` | Измеренный объём 6 614 491 136 байт. Перед удалением проверены process args, executable/cwd/root, memory maps, открытые FD и все container mounts. Сохранены используемая версия, три самых новых версии и все версии младше 60 дней. |

Dependency installers и Docker builds перед чисткой download caches не были
обнаружены. BuildKit сам управляет зависимостями cache; применён фильтр
возраста, актуальный cache сохранён. Это разовая техническая операция,
новая автоматическая retention policy не вводилась.

Одна из 11 старых установок VS Code Server содержит нулевой immutable-файл
`node (deleted)`. Первая попытка удаления остановилась на его защите; четыре
предыдущих каталога уже были удалены, содержимое защищённой установки по
измерению осталось прежним. Защита не снималась. Перед продолжением
проверены атрибуты оставшихся установок; защищённая версия сохранена целиком,
удалены только шесть остальных. Таким образом, итог — **10 удалённых, одна
защищённая сохранена**. VS Code user settings, globalStorage, extensions и
активный сервер не затронуты.

## Что проверено и сохранено

- Основной production checkout занимал около 561 GiB: `static` около
  **534 GiB**, `backups` около **22 GiB**, `data` около 3,4 GiB. Эти каталоги
  целиком исключены из очистки. Также сохранены outputs, Git, source/worktree
  content, `.env`, `.env.postgres`, runtime tariffs и история логов.
- Проверены крупные каталоги `/root`, `/var`, `/tmp`, `/opt`, оставшаяся
  корневая файловая система, inode usage и крупные файлы корня. Остались
  нетронутыми базы `/var/lib`, Docker volumes, swap/system files, журнал
  systemd, browser runtimes, uv environments и временные файлы неизвестного
  назначения. Сам размер каталога не был основанием для его удаления.
- Перед удалениями выполнен PostgreSQL snapshot с
  `default_transaction_read_only=on`: 47 225 saved-reference записей,
  26 trend-asset записей и snapshots 1 492 задач из окна предыдущего аудита.
  Получено 47 869 уникальных локальных путей: **44 048 существовали**,
  **3 821 уже отсутствовали** (исторические пропуски из аудита).
- Все 44 048 существовавших файлов после очистки проверены по тому же пути:
  **ноль пропавших, ноль изменивших размер, inode или mtime**. Это проверка
  сохранности snapshot, а не утверждение о наличии всех исторических файлов
  или исправлении существующих пропусков. Содержимое медиа не читалось и
  не переписывалось.
- Все **41 контейнер** из начального snapshot сохранили image, время запуска,
  restart count и mount mappings. Контейнеры не останавливались и не удалялись.
- Сохранены production `banano-kling-bot:local`, оставшийся
  `banano-kling-bot:rollback-before-c221dd2`, работающий KSU image, его
  предыдущий release и именованный KSU rollback. Дополнительного image prune
  в этой операции не было. `fix-c221dd2` уже отсутствовал при начальной
  инвентаризации этой операции.
- `.env` и `data/price.json` совпали по SHA-256 с начальным snapshot.
  Backend остался на `c9cf187497c1d9725424bf300b78a27a33e04e02`, healthy,
  restart count 0, время запуска не изменилось. Bind mounts data/uploads/
  outputs/backups/logs сохранены.
- Local/public `/health` вернули HTTP 200/status ok. Публичный Mini App
  `revision.txt` совпал с тем же SHA. `docker exec banano-kling-bot python -m
  pip check` вернул `No broken requirements found`.
- Published mobile Chromium smoke прошёл: viewer/admin counters, category
  pagination, preview, смена роли, repeat UI и admin history. API/media
  подменены fixtures; реальных генераций/оплат/уведомлений не было.

## Evidence и пределы

Приватные snapshots и логи операций хранятся в mode-0700
`/tmp/neuromix-disk-cleanup-20261020`; пользовательские пути/URL, данные
платежей, credentials и сырые DB rows в Git не добавлены. Измерения свободного
места — snapshots на работающем общем хосте, где параллельно продолжается
обычная работа приложений.

Использованы Bambale0/skills diagnosing-bugs (измерение до/после),
Bambale0/claw operational review checklist и anthropics/skills webapp-testing.
Исходная task-ветка создана от `origin/tanyapi`
`0c6c7062045dc2a2cf9cdd5f21152bdecfb8efbd`. Изменения Git — только этот
отчёт и execution ledger; schema/config/admin/provider/payment изменений нет.
Ручного deploy не было. Тесты приложения целиком не перезапускались, поскольку
код приложения не менялся; применены runtime/file-preservation/browser checks.

Существующие отсутствующие референсы, зависшая Wan-задача и вопросы полноты
маркеров возврата из аудита не исправлялись этой очисткой. Защищённые медиа и
резервные копии требуют собственной процедуры retention/restore; удаление
по возрасту без проверки владельцев/связей не выполнялось.
