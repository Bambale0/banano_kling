# 2026-11-21 — Genjutsu: сохранять промпт и модель при «Редактировать результат»

## Исходная проблема

- База: `tanyapi` `797f49bbde46fe70b15a55d9a2013a700263e1d3`; исходный SHA совпадал с production OCI и публичным `revision.txt`.
- Подтверждённый сценарий у администратора `@only_tany`: после успешной операции Light повторное редактирование полученного видео создаёт новый проект с пустым промптом и обычным Motion Transfer.
- Причина: обработчик кнопки `Редактировать результат` передавал в `newWork()` безусловный `freshPlan()` с новым `source_asset_id`. В отличие от `Повторить с настройками`, выбор режима, промпт, `preserve`, качество и ссылки на фото терялись до `save_project` и `quote`.
- API Higgsfield допускает пустой промпт; здесь не меняем контракт провайдера, тарифы и логику допустимых пустых запросов.

## Решение

- При редактировании результата обычного (не защищённого) запуска создавать новый проект от конфигурации **выбранного завершённого шага**, а в качестве исходного видео использовать сохранённый результат этого шага.
- Переносить `operation` (включая Light), `prompt`, `preserve`, `resolution`, `references` с ролями и подписями, `preset_id`, число вариантов. Создаётся один следующий шаг, не повторяется автоматически предыдущая цепочка.
- Скрытые/private рецепты остаются закрыты: если API не возвращает разрешённый `run.plan` либо `run.private_recipe` истинно, не копировать скрытые настройки. Кнопка открывает чистый промпт и пустые референсы с новым исходным видео, но сохраняет уже публично раскрытые `operation` и `resolution` выбранного шага.
- Кнопка `Новый проект` по-прежнему создаёт независимый пустой черновик.
- После переноса выводить пояснение проверить параметры до расчёта. Ни один переход не вызывает платного `start` автоматически.
