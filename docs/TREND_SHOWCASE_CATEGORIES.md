# Категории трендов — NEUROMIX / tanyapi

## Назначение

Категории — редакторские папки поверх опубликованных трендов, а не тип генерации. Старое поле user_prompts.category по-прежнему обозначает photo/video/other. Приватные промпты, референсы, настройки, стоимость и ссылки на генерацию не меняются.

## Структура данных

- trend_categories: id, title, emoji, sort_order, is_visible, revision, created_at, updated_at.
- trend_category_items: category_id, prompt_id, sort_order, badge, badge_until.
- Один тренд может состоять в нескольких категориях без дублирования записи user_prompts.
- Категории можно переставлять; порядок внутри папки независим.
- Не распределённые тренды доступны в виртуальной категории «Другие тренды»; в админке она называется «Без категории».
- Скрытые категории не отображаются и не открываются для обычного пользователя.
- Удаление категории не удаляет сам тренд, задачи, медиа или ссылки.

Миграции идемпотентно применяются в bot/database._ensure_prompt_feed_schema при init_db; PostgreSQL использует execute_native_ddl. Схема для чистой PostgreSQL также обновлена в schema_postgres.sql.

## HTTP API

Все маршруты POST под /mini-app/api, проверка подписанного Telegram init_data на сервере, заголовок Cache-Control: no-store.

| Маршрут | Назначение |
|---|---|
| /trends/catalog | Категории с ограниченным числом первых карточек |
| /trends/category | Полная категория с page и limit |
| /admin/trends/categories | Управление категориями, размещением и бейджами |

Admin op: create, update, delete, reorder, set_items, move_item, set_trend_categories, set_badge, search_trends. Модификации защищены проверкой revision; stale-операция возвращает HTTP 409. При полном переназначении категорий одного тренда PostgreSQL блокирует строку самого тренда (FOR UPDATE), SQLite использует BEGIN IMMEDIATE, чтобы параллельные запросы не объединяли два противоречивых набора. Для перестановки всех категорий PostgreSQL предварительно блокирует строки в порядке ID (FOR UPDATE), а SQLite берёт writer-lock до чтения: противоположные запросы двух администраторов завершаются нормальным revision conflict вместо deadlock. Админский поиск возвращает только опубликованные тренды.

Все карточки проходят sanitize_prompt_for_public: скрытые тексты, приватные настройки модели, исходные значения пользовательских полей и внутренние данные модерации не попадают в ответы.

Middleware дополнен для совместимого API /api/v1/prompts, включая signed header на GET без JSON-тела. HTTP-регрессионные тесты проверяют права и приватность. Отказ проверки обязательной подписки возвращает 403 с исходным текстом для пользователя.

### Неизменяемый журнал административных действий

Все восемь операций изменения каталога записывают событие в trend_catalog_audit
в той же SQLite/PostgreSQL транзакции: create, update, delete, reorder,
set_items, set_trend_categories, move_item и set_badge. Запись содержит
проверенный Telegram ID администратора, действие, ID категории/тренда,
структурированные метаданные до и после изменения и точное время с микросекундами.
Внутренние вызовы без пользователя маркируются actor_telegram_id = 0.

В журнал никогда не попадают исходные промпты, приватные ссылки, media assets,
балансы и пользовательские фотографии. PostgreSQL/SQLite блокируют UPDATE
и DELETE записей аудита. При ошибке вставки события изменение категории
откатывается целиком. Историю можно прочитать только через подписанное
административное действие history (не более 100 записей) или в админ-панели
через кнопку «Показать историю».


## Telegram Mini App

- Живая витрина с горизонтальными каруселями и разделами по категориям.
- Кнопка «Все» открывает страницу категории с пагинацией.
- Видео запускается при видимости, не более двух одновременно. Save Data и reduced-motion выключают автозапуск.
- Нажатие на карточку открывает просмотр со звуком и кнопки «Повторить» и «Поделиться».
- Повторы используют прежний TrendRunnerDialog / WAN / Genjutsu, защищённые серверные рецепты и прежние расчёты. Для Genjutsu отображаемая цена подгружается через существующий authenticated recipe_costs, а не через приблизительный тариф; отсутствие цены не блокирует просмотр.
- Админ в просмотре карточки сохраняет прежние действия «Редактировать» (обновить preview) и «Убрать тренд» (деактивировать), не теряя старые сценарии управления.
- Админская панель: создание папок, управление видимостью, порядок, поиск и добавление готовых трендов, перенос, «Новинка» с датой.
- Новая публикация может быть привязана к нескольким категориям; если привязка не удалась, сообщение ясно говорит, что тренд уже опубликован.
- Успешная загрузка нового каталога не вызывает лишний legacy-запрос промптов. При недоступности нового API работает старый экран. Во время переключения админской папки устаревшие элементы скрыты и запись заблокирована до подтверждённого ответа.

## Подготовка облегчённых видео и постеров

Текущая реализация bot/services/trend_preview_service.py использует FFmpeg, оригиналы сохраняются неизменными. Публичный запрос каталога берёт уже подготовленные производные из кэша и не запускает FFmpeg.

Для старого контента используйте ограниченную пакетную обработку в контейнере. Без флага --execute скрипт ничего не меняет:

    python -m scripts.backfill_trend_previews --limit 20
    python -m scripts.backfill_trend_previews --limit 20 --execute

Отбор выполняется по видео-расширениям до SQL LIMIT, обычные изображения не отбирают места из партии. Следующая партия доступна через --before-id (минимальный ID предыдущего батча). Не запускать обработку сотен больших файлов на production во время пиковых генераций.

## Smoke / rollback

1. Backend тесты HTTP + SQLite, TS/Jest и Next production build.
2. Ветка feature -> PR в tanyapi; CI, squash auto-merge и автодеплой через защищённый процесс из AGENTS.md.
3. После деплоя проверить точный SHA, health, открытие карточек на iOS/Android, скрытые категории, ссылки и доставку готовых результатов в Mini App.
4. Любая платная генерация — только после отдельного разрешения.
5. Откат кода безопасен: новые таблицы не используются старыми пайплайнами. Не удалять таблицы при rollback.

## Видимый счётчик успешных запусков — 16.10.2026

Каждая плитка живого каталога, карточка просмотра и резервный список трендов должны **явно показывать** число **успешных запусков**: «✅ 328 запусков» на плитке и «✅ Успешных запусков: 328» в деталях. Для нулевого показателя выводить **0**, а при отсутствии метрики в API — **—**, не подменять неизвестное значение нулём и не скрывать строку.

Данные берутся из `successful_runs_count`, которое backend рассчитывает по связанным с трендом уникальным `task_id` со статусом `completed`. `uses_count` отражает принятые попытки, в том числе неуспешные, и **не подходит**. Пользователь должен видеть один и тот же показатель для фото и видео, на главной странице категорий, на странице выбранной папки, в предпросмотре и в резервной сетке при недоступности `/trends/catalog`.

Путь: `bot/handlers/trend_success_compat.py` / `bot/trend_catalog.py` → `/trends/catalog`, `/trends/category`, legacy `/prompts` → `components/trend-showcase.tsx`, `components/tabs/trends-tab.tsx`. Цены/вознаграждения/реферальная атрибуция при этой правке не изменяются. Браузерный контракт `e2e/trend-category-showcase.mjs` проверяет 328, 0, отсутствие метрики и fallback.
