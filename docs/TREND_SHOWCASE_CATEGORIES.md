# Категории трендов — NEUROMIX / tanyapi

## Назначение

Категории — редакторские папки поверх опубликованных трендов, а не тип генерации. Старое поле user_prompts.category по-прежнему обозначает photo/video/other. Приватные промпты, референсы, настройки, стоимость и ссылки на генерацию не меняются.

## Структура данных

- trend_categories: id, title, emoji, sort_order, is_visible, revision, created_at, updated_at.
- trend_category_items: category_id, prompt_id, sort_order, badge, badge_until.
- Один тренд может состоять в нескольких категориях без дублирования записи user_prompts.
- Категории можно переставлять; порядок внутри папки независим.
- Не распределённые тренды доступны в виртуальной категории «Другие тренды»; в админке она называется «Без категории».
- Скрытые категории не отображаются и не открываются для обычного пользователя.
- Удаление категории не удаляет сам тренд, задачи, медиа или ссылки.

Миграции идемпотентно применяются в bot/database._ensure_prompt_feed_schema при init_db; PostgreSQL использует execute_native_ddl. Схема для чистой PostgreSQL также обновлена в schema_postgres.sql.

## HTTP API

Все маршруты POST под /mini-app/api, проверка подписанного Telegram init_data на сервере, заголовок Cache-Control: no-store.

| Маршрут | Назначение |
|---|---|
| /trends/catalog | Категории с ограниченным числом первых карточек |
| /trends/category | Полная категория с page и limit |
| /admin/trends/categories | Управление категориями, размещением и бейджами |

Admin op: create, update, delete, reorder, set_items, move_item, set_trend_categories, set_badge, search_trends. Модификации защищены проверкой revision; stale-операция возвращает HTTP 409. Админский поиск возвращает только опубликованные тренды.

Все карточки проходят sanitize_prompt_for_public: скрытые тексты, приватные настройки модели, исходные значения пользовательских полей и внутренние данные модерации не попадают в ответы.

Middleware дополнен для совместимого API /api/v1/prompts. HTTP-регрессионные тесты проверяют права и приватность.

## Telegram Mini App

- Живая витрина с горизонтальными каруселями и разделами по категориям.
- Кнопка «Все» открывает страницу категории с пагинацией.
- Видео запускается при видимости, не более двух одновременно. Save Data и reduced-motion выключают автозапуск.
- Нажатие на карточку открывает просмотр со звуком и кнопки «Повторить» и «Поделиться».
- Повторы используют прежний TrendRunnerDialog / WAN / Genjutsu, защищённые серверные рецепты и прежние расчёты.
- Админская панель: создание папок, управление видимостью, порядок, поиск и добавление готовых трендов, перенос, «Новинка» с датой.
- Новая публикация может быть привязана к нескольким категориям; если привязка не удалась, сообщение ясно говорит, что тренд уже опубликован.

## Подготовка облегчённых видео и постеров

Текущая реализация bot/services/trend_preview_service.py использует FFmpeg, оригиналы сохраняются неизменными. Публичный запрос каталога берёт уже подготовленные производные из кэша и не запускает FFmpeg.

Для старого контента используйте ограниченную пакетную обработку в контейнере. Без флага --execute скрипт ничего не меняет:

    python -m scripts.backfill_trend_previews --limit 20
    python -m scripts.backfill_trend_previews --limit 20 --execute

Следующая партия доступна через --before-id (минимальный ID предыдущего батча). Не запускать обработку сотен больших файлов на production во время пиковых генераций.

## Smoke / rollback

1. Backend тесты HTTP + SQLite, TS/Jest и Next production build.
2. Ветка feature -> PR в tanyapi; CI, squash auto-merge и автодеплой через защищённый процесс из AGENTS.md.
3. После деплоя проверить точный SHA, health, открытие карточек на iOS/Android, скрытые категории, ссылки и доставку готовых результатов в Mini App.
4. Любая платная генерация — только после отдельного разрешения.
5. Откат кода безопасен: новые таблицы не используются старыми пайплайнами. Не удалять таблицы при rollback.
